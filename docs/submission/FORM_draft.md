## 1. 해결하고자 했던 문제 (Problem Definition) — 300자 내외

공공데이터 API를 붙이는 개발자는 "연결은 됐는데 데이터가 이상한" 상황에서 가장 오래 막힙니다.
200 OK가 오고 코드도 안 죽는데 페이지 경계에서 레코드가 새거나, 필드가 조용히 비거나,
요청한 범위와 받은 범위가 어긋납니다. 에러가 없으니 어디를 봐야 할지 모르고, 결국 눈으로
응답을 훑으며 며칠을 씁니다. 여기에 LLM을 붙이면 더 위험합니다. 모델이 "고쳤습니다"라고
말하면 그 말이 곧 결론이 되기 때문입니다. 저희는 **고쳤다는 판정을 모델이 내리지 않는**
API 진단·복구 도구를 만들었습니다.

## 2. 서비스 소개 및 주요 기능 (Solution) — 500자 내외

`api-doctor`는 API 연동 코드를 받아 결함을 진단하고 고친 뒤, **그 수리가 진짜인지를
LLM 없이 검증하는** CLI 도구입니다. 원칙은 하나입니다. **LLM은 어디를 볼지만 정하고,
무엇이 참인지는 LLM이 없는 코드가 정합니다.** 모델이 도는 구역이 검증기·기대값·
네트워크에 닿지 못하도록 시스템을 네 구역으로 나누고, 그 경계를 CI가 강제합니다.

사용자 흐름:
1. `api-doctor run <코드>` — 네트워크가 끊긴 컨테이너에서 실행합니다.
   실행 전 격리가 실제로 작동하는지 5종 자가검사로 증명합니다.
2. **고정 검증기**가 실행·필드·값·전체성을 봅니다. 원본이 이미 정상이면
   **모델을 한 번도 부르지 않고** 끝납니다.
3. 결함이 확인될 때만 1+4 에이전트 팀을 부릅니다.
4. 감사자는 수리자의 설명을 못 받습니다. 런타임이 중립 봉투를 새로 조립해
   관측 증거만 넘기므로, 직접 probe를 돌려야 결론을 낼 수 있습니다.
5. **종료 게이트**가 네 조건을 전부 만족할 때만 성공으로 승격합니다. 우회는 없습니다.

## 3. 활용한 핵심 기술 및 AI 모델 (Tech Stack)

### NVIDIA
| 항목 | 내용 |
|---|---|
| 모델 | **`nvidia/nemotron-3-super-120b-a12b`** (reasoning 모델) |
| 엔드포인트 | NVIDIA NIM — `https://integrate.api.nvidia.com/v1` (OpenAI 호환) |
| 발급 | build.nvidia.com 무료 등급 |
| 프로파일링 | **NeMo Agent Toolkit** 형식의 역할별 구간 리포트 (`standardized_data_all.csv`·간트 차트 대응) |

reasoning 모델 특성상 추론 토큰이 `completion_tokens`에 함께 잡혀, 역할별 출력 상한을
따로 잡았습니다(수리자 12,288 / 나머지 3,072).

### 에이전트 하네스
- **deepagents 0.7.19** — 메인 하네스
- **LangChain / LangGraph** — `wrap_tool_call` 미들웨어 훅에서 `task` 위임을 가로채
  예산·권한·중복 위임을 검사합니다
- 기본 파일시스템 백엔드가 호스트에 닿지 않는 `StateBackend`임을 확인하고,
  `FilesystemMiddleware(tools=["read_file"])`로 쓰기 도구를 제거했습니다
- 자동 요약 미들웨어는 비활성화했습니다 — 메인의 모델 예산을 몰래 먹고 있었습니다

### 격리 실행
- Docker `--network none --read-only --cap-drop ALL --security-opt no-new-privileges
  --user 65534:65534 --pids-limit 32 --memory 512m --cpus 1 --tmpfs /tmp`
- 후보 코드와 브로커 사이는 JSONL IPC. API 키는 `{KEY}` 자리표시자로만 전달되어
  후보 코드가 실제 키를 읽을 수 없습니다

### 그 외
Python 3.12 · uv · Typer · Rich · Pydantic · httpx · pytest
